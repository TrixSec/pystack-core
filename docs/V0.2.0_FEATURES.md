# pystack-core v0.2.0 Documentation

## HTTP Client Module

The HTTP Client module provides a production-ready HTTP client with automatic retry, timeout management, metrics collection, and circuit breaker functionality.

### Features

- **Automatic Retry**: Configurable retry policy with exponential backoff
- **Timeout Management**: Configurable request timeouts
- **Metrics Collection**: Track request counts, success rates, and latency
- **Circuit Breaker**: Prevent cascading failures
- **Authentication**: Built-in support for basic auth and bearer tokens
- **Middleware Pipeline**: Request/response middleware support

### Usage

```python
import asyncio
from pystack_core import HttpClient, HTTPMethod, RetryPolicy

async def main():
    # Create HTTP client with custom retry policy
    retry_policy = RetryPolicy(max_retries=5, backoff_factor=2.0)
    client = HttpClient(timeout=30.0, retry_policy=retry_policy)
    
    # Add authentication
    client.add_auth("basic", username="user", password="pass")
    # or
    client.add_auth("bearer", token="your-token")
    
    # Make requests
    response = await client.get("https://api.example.com/data")
    print(f"Status: {response.status_code}")
    print(f"Success: {response.success}")
    
    # Get metrics
    metrics = client.get_metrics()
    print(f"Total requests: {metrics['requests_total']}")
    print(f"Success rate: {metrics['requests_success'] / metrics['requests_total']}")
    
    await client.close()

asyncio.run(main())
```

### Circuit Breaker

```python
from pystack_core.http import CircuitBreaker

async def protected_request():
    breaker = CircuitBreaker(failure_threshold=3, recovery_timeout=60.0)
    
    async def make_request():
        # Your request logic here
        pass
    
    try:
        result = await breaker.call(make_request)
        return result
    except Exception as e:
        print(f"Circuit breaker error: {e}")
```

## Cache Module

The Cache module provides multi-backend caching with support for memory, Redis, and disk storage.

### Features

- **Multiple Backends**: Memory, Redis, and disk storage
- **TTL Support**: Time-to-live for cache entries
- **LRU Eviction**: Automatic eviction of least recently used items
- **Statistics**: Track hit rates, cache size, and performance
- **Batch Operations**: Get/set multiple items efficiently

### Usage

```python
import asyncio
from pystack_core import MemoryCache, CacheManager

async def main():
    # Memory cache
    cache = MemoryCache(max_size=1000, default_ttl=3600)
    
    # Set and get values
    await cache.set("user:1", {"name": "John", "age": 30})
    user = await cache.get("user:1")
    print(user)
    
    # With TTL
    await cache.set("session:abc", "data", ttl=300)  # 5 minutes
    
    # Statistics
    stats = cache.get_stats()
    print(f"Hit rate: {stats.hit_rate:.2%}")
    
    # Cache manager for multiple backends
    manager = CacheManager()
    await manager.set("key", "value")
    value = await manager.get("key")

asyncio.run(main())
```

## Database Module

The Database module provides unified database access with support for SQLite and PostgreSQL.

### Features

- **Multiple Backends**: SQLite and PostgreSQL support
- **Transaction Management**: Automatic transaction handling
- **Connection Pooling**: Efficient connection management
- **Query Results**: Structured result objects with metadata
- **Context Managers**: Pythonic transaction handling

### Usage

```python
import asyncio
from pystack_core import SQLiteDatabase, DatabaseManager

async def main():
    # SQLite database
    db = SQLiteDatabase(":memory:")
    await db.connect()
    
    # Create table
    await db.execute("CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, email TEXT)")
    
    # Insert data
    await db.execute("INSERT INTO users (name, email) VALUES (?, ?)", ("John", "john@example.com"))
    
    # Query data
    user = await db.fetch_one("SELECT * FROM users WHERE name = ?", ("John",))
    print(user)
    
    # Transaction management
    async with db:
        await db.execute("INSERT INTO users (name, email) VALUES (?, ?)", ("Jane", "jane@example.com"))
    
    await db.disconnect()

asyncio.run(main())
```

### Database Manager

## Integration Examples

### Web Service with HTTP, Cache, and Database

```python
import asyncio
from pystack_core import (
    HttpClient, CacheManager, DatabaseManager,
    SQLiteDatabase, MemoryCache
)

class APIService:
    def __init__(self):
        self.http = HttpClient(timeout=30.0)
        self.cache = CacheManager()
        self.db = DatabaseManager()
        self.cache.register_backend("memory", MemoryCache())
    
    async def get_user_data(self, user_id: int):
        # Try cache first
        cached = await self.cache.get(f"user:{user_id}")
        if cached:
            return cached
        
        # Query database
        user = await self.db.fetch_one(
            "SELECT * FROM users WHERE id = ?",
            (user_id,)
        )
        
        if user:
            # Cache for 5 minutes
            await self.cache.set(f"user:{user_id}", user, ttl=300)
        
        return user
    
    async def fetch_external_api(self, url: str):
        # Add caching for external API calls
        cached = await self.cache.get(f"api:{url}")
        if cached:
            return cached
        
        response = await self.http.get(url)
        if response.success:
            await self.cache.set(f"api:{url}", response.json_data, ttl=60)
        
        return response.json_data

async def main():
    service = APIService()
    await service.db.connect()
    
    try:
        user = await service.get_user_data(1)
        print(user)
    finally:
        await service.db.disconnect()
        await service.http.close()

asyncio.run(main())
```

## Performance Considerations

### HTTP Client

- Use connection pooling for high-throughput scenarios
- Configure appropriate timeout values based on your use case
- Monitor metrics to identify performance bottlenecks
- Use circuit breakers to prevent cascading failures

### Cache

- Choose appropriate backend based on your needs:
  - Memory: Fastest, limited by RAM
  - Redis: Fast, distributed, persistent
  - Disk: Slower, persistent, large capacity
- Set appropriate TTL values to balance freshness and performance
- Monitor hit rates to optimize cache strategy

### Database

- Use connection pooling for high-concurrency scenarios
- Keep transactions short to avoid locking
- Use prepared statements for repeated queries
- Consider read replicas for read-heavy workloads

## Troubleshooting

### HTTP Client Issues

- **Timeout errors**: Increase timeout value or check network connectivity
- **Retry failures**: Adjust retry policy or check upstream service health
- **Authentication errors**: Verify credentials and auth method

### Cache Issues

- **Low hit rate**: Review TTL values and cache key strategy
- **Memory issues**: Reduce max_size or use disk backend
- **Stale data**: Adjust TTL values based on data freshness requirements

### Database Issues

- **Connection errors**: Verify database is running and credentials are correct
- **Transaction deadlocks**: Keep transactions short and avoid long-running transactions
- **Performance issues**: Use indexes and optimize queries
